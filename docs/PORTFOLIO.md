## Two-minute demo script

**0:00 — Frame the problem.**
"Analysts spend hours answering repetitive questions. The hard part isn't
running the query — it's the follow-up: *why*. So I built an assistant that goes
all the way to the explanation."

**0:15 — Show the app.** Open Streamlit. Point at the KPI rail. "Real data —
2.5 years, 27,000 orders."

**0:25 — Ask the flagship question.** Click *"Why did revenue drop in March?"*

**0:35 — Read the answer aloud, top to bottom.**
"Revenue down 17.6%. Electronics explains 92% of that. Two enterprise accounts
dropped 87% and 84% — that's churn, not seasonality. And it flagged that
February has 28 days, so per-day the drop is actually worse, −25.6%."

> Pause here. The caveat is the moment people realise it isn't a toy.

**0:55 — The waterfall.** "This chart is the whole month in one glance —
baseline, each driver, where we landed."

**1:10 — Open the SQL tab.** "Every number traces back to a query. The model
writes SQL and writes English. It never does arithmetic — that's how you avoid
confidently wrong metrics."

**1:25 — Open the Trace tab.** "Every decision is logged: what it parsed, which
branch it took, which dimensions it scanned."

**1:40 — Show a second question.** Type *"top 10 products by revenue in 2026"*.
"Different intent, different chart, automatically."

**1:50 — Close on engineering.**
"34 tests, all offline. The key one asserts the engine independently rediscovers
the story planted in the data — so I'm testing the claim, not just the plumbing.
And with no API key it falls back to a rule-based engine, so it never has a dead
demo."

## Questions you will get

**"How do you stop it hallucinating numbers?"**
Structurally, not by prompting harder. The LLM does two jobs: write SQL, and
write prose from a facts block I computed. Every figure comes from a SQL
aggregate. If the model invented one, I'd catch it — I have the ground truth.

**"What if it writes bad SQL?"**
Three layers. The guard rejects anything that isn't a single read-only SELECT.
If it's valid but errors at execution, the error goes back for one repair
attempt — one, not a loop, because unbounded retries against a paid API get
expensive. If that fails, the deterministic template engine answers.

**"How does it decide what caused the drop?"**
It doesn't ask the LLM. For each dimension it pulls the metric for both periods,
outer-joins them, and computes each segment's share of the *total change*. The
outer join matters — a customer who bought in February and nothing in March has
no March row, and an inner join would silently delete the biggest finding.

**"Why the offline mode?"**
Three reasons. The demo never dies. The tests are deterministic and free. And it
forced a clean separation between deciding *what to compute* and deciding *how
to phrase it* — which is better architecture regardless.

**"Would this work on our real warehouse?"**
The schema description is generated by introspection, so prompts adapt on their
own. You'd swap the connection for SQLAlchemy and add a metric registry — a
single definition of "active customer" so every query agrees. That governance
problem is the actual hard part in production, harder than the SQL generation.

**"What's the weakest part?"**
Two things. First, it's correlational — it finds *what* moved, not *why*, and I
label it that way rather than overclaiming causation. Second, the parser is
rule-based, so unusual phrasings fall back to the LLM path; with a key that's
fine, offline it degrades to a reasonable default. If I extended it, I'd add
multi-turn context so follow-ups resolve against the previous question.

**"How long did it take?"**
The engine came together quickly. Most of the time went into the data generator —
getting a shock that was findable but not obvious took real tuning, and it's
what makes the demo land.

## Making it yours

Do at least two of these before you present it, so it's your project and not a
walkthrough you followed:

- **Change the domain.** Regenerate as SaaS subscriptions, logistics, or
  healthcare claims. Edit the categories and shock parameters in
  `data/generate_data.py`, retune until the printout looks right.
- **Add a metric you care about.** Retention, repeat-purchase rate, discount
  depth. Add one entry to `METRICS` in `app/question.py` — analyzer, templates
  and charts all pick it up.
- **Add multi-turn follow-ups.** The highest-value extension and the most
  commonly asked-about.
- **Deploy it.** Streamlit Community Cloud is free. A live URL on your resume
  beats a GitHub link.
- **Record a 90-second Loom.** Most reviewers won't clone your repo. They will
  watch a minute and a half.
